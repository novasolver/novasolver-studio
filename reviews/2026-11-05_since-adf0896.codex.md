### Medium — Recognize Windows native-crash headers

**What goes wrong:** A Windows worker crashes with an access violation → `status()` reports thread/stack information instead of the crash reason.

Reproduced using a separate Python process with `faulthandler.enable(); faulthandler._read_null()`. It emitted:

```text
Windows fatal exception: access violation
```

Passing that captured output through `jobs.status()` with mocked file access returned:

```text
 | Current thread … (most recent call first): |   File "<string>", line 1 in <module>
```

The GUI and MCP receive this incomplete message through `commands.job_status()`.

**Why:** Line 96 recognizes only headers beginning with `Fatal Python error`. Windows native exceptions use `Windows fatal exception:`, so processing falls back to the final three log lines and discards the cause. The added test covers only the former format.

**Suggested fix:** Recognize both header prefixes and add a regression test using a Windows access-violation log.
