## From the second opinion (`reviews/2026-10-29_since-8fadfa5.codex.md`)
1. **High. Contact with large deformation** uses reference normals and fixed node pairs. Implementing true
   finite-sliding contact is out of scope: detect it and refuse clearly instead. When `large_deformation` is on and
   any interface is non-bonded, raise a translated error (`err.contact_large_deformation`) explaining that contact
   is small-sliding/small-rotation only; the readiness check shows the same. Document it in `docs/CONTACT_NONLINEAR.md`.
2. **High. Modal ignores `displacement` and spring supports.** Apply zero-displacement components as constraints in
   `run_modal` (and in the CalculiX modal deck); add spring stiffness to K. A non-zero prescribed displacement in a
   modal case is ignored with a visible note (like loads).
3. **High. Spring unit switching** (N/m ↔ N/mm) keeps the number: add a stiffness dimension to
   `frontend/src/lib/units.ts` (N/m = 1, N/mm = 1000) and make `NumberInput` refuse a unit change it cannot convert.
4. **High. Uniform body temperatures** overwrite shared nodes: use per-element temperatures (initial strain per
   element / Gauss point) for `uniform` per-body temperatures, so the result does not depend on dictionary order.
5. **Medium. Preset change keeps the old material law** (`model`, `H`): selecting a preset replaces the material's
   constitutive fields with the preset's (model default `linear`).
6. **Medium. CalculiX collapse verification** reads `r['curve']`: pass the parsed curve/snapshots into the reference
   response; handle a missing history explicitly.
7. **Medium. Load paths bypass the history memory estimate**: bound total increments (path travel / increment and
   cut-backs) in the estimate, validate `path` values (finite, |value| ≤ 100 × the nominal load factor, at most 50
   entries) in `update_case`, and enforce a runtime snapshot cap (keep every k-th snapshot plus the last when over
   the cap, say 200).
8. **Low.** `path=[0]` raises `UnboundLocalError`: initialise the history; a schedule with no effective increment
   returns the initial state or a validation error.
