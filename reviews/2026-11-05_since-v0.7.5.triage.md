# Triage: second opinion on the changes since v0.7.5 (Codex gpt-6.1-sol, 2026-11-05)

Report: `2026-11-05_since-v0.7.5.codex.md`. Each finding was read in the code, and all three are real. They came from this release's own changes.

| # | Severity | Finding | Outcome |
|---|---|---|---|
| 1 | High | `_pcg_best` trusted the recurrence residual: on an ill-conditioned system it reported 1e-9 while the true residual was 0.02, and `_amg_cg` accepted the answer | **fixed**: the residual returned is recomputed from `b - Ax`, so such a solve goes on to the next AMG set-up and then the direct solve. `test_the_iterative_solver_judges_the_true_residual` |
| 2 | Medium | The Gmsh-order fallback in `canonical_tets` was not repeatable: a second pass swapped columns 8 and 9 back, so `solve_modal` failed on a valid curved mesh | **fixed**: `_midsides_by_position` keeps the layout that neighbouring elements agree on, and takes the nearer one when elements share no midside node. Added to `test_midside_columns_follow_gmsh_order_when_geometry_cannot_tell` |
| 3 | Medium | Finer mesh retries reused the same STL surface, so a failure caused by the surface got the same surface again | **fixed**: `_size_factor` also scales the PyMeshLab target. `test_a_finer_mesh_retry_also_refines_the_stl_surface` checks the argument; recovery on a real failing STL was not run |

Also checked after this report, because the retries are new: a retry at a finer size can change the element count of one level in a mesh study. The GCI uses the real element counts, and `refined` fails the study unless each level has at least 1.3 times the elements of the one before. So a coarse level that came out finer fails the study instead of passing. No change.

Codex reported no findings on security, the MCP contract, UI or packaging. It did not run the full backend tests or the validation suite.
