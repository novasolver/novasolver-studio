### 1. High — Readiness warnings are discarded

**What goes wrong:** Build a 60-point modal cantilever surrogate varying `boundaries.x1.force`. The solver ignores those forces and returns constant frequencies. Normal readiness validation warns `modal_loads_ignored`, but the surrogate omits that warning.

**Why:** `_solve()` retains only readiness errors. Its saved warnings come exclusively from `results.payload()`, which does not repeat `modal_loads_ignored`. `_finish_model()` consequently cannot preserve the warning. In-memory checks confirmed both the readiness warning and its disappearance from the saved point.

**Suggested fix:** Preserve readiness warnings alongside result warnings, including their explanatory messages. Return relevant warnings when starting the build and carry them through status and predictions.

### 2. High — Mesh uncertainty does not match the training mesh

**What goes wrong:** Build from a case using the default normal mesh. Training values use that mesh, but mesh checks report the fine-mesh GCI.

For example, convergence values of `112 → 103 → 100` at mesh spacings `1 → 0.5 → 0.25` produce a reported GCI of **1.875%** and extrapolated value `98.5`. The model learns the normal-mesh value `103`, whose difference from that extrapolation is approximately **4.57%**.

**Why:** Ordinary `_solve()` calls preserve `case["mesh"]["size"]`. Convergence jobs always run coarse, normal and fine levels; `run_worker.run_study()` computes GCI relative to the fine result. The surrogate stores that GCI without identifying the different training resolution.

**Suggested fix:** Train on the checked fine-mesh resolution, or calculate and label uncertainty for the actual training mesh. Persist the training mesh and checked quantity with the model.

### 3. Medium — Concurrent resumes launch duplicate builders

**What goes wrong:** Send two simultaneous `control_surrogate(..., action="resume")` requests for a stopped study. Both can launch a worker. If both read the same completed-point list, they solve and append the same indices; later, one can delete the frozen case while the other still needs it.

**Why:** Reading state, checking `_alive()` and spawning are separate operations with no study lock or atomic ownership claim. An in-memory concurrent reproduction produced **two `_spawn()` calls**.

**Suggested fix:** Serialize resume operations with a per-study process lock. Claim ownership and recheck state under that lock before launching a worker.

### 4. Medium — Integer-only parameters fail after the build starts

**What goes wrong:** Specify `physics.modes` with `min=1`, `max=3`, omitting the unit. Both endpoint edits succeed. The first Sobol point generates approximately `1.540368367`, which `store.apply_changes()` rejects, failing the builder.

**Why:** The tool promises numeric fields supported by `update_case`, but generates every parameter continuously. Endpoint validation cannot identify integer-only fields, and `_solve()` calls `clone_case()` before its cleanup block.

**Suggested fix:** Validate parameter types before creating the study. Reject unsupported discrete parameters with an actionable error, or generate valid integer designs explicitly.

### 5. Medium — Velocity outputs have incorrect units

**What goes wrong:** Default cavity predictions label `umin_center` as `"-"`; default channel predictions do the same for `umax_outlet`. Both metrics contain velocities in **m/s**.

**Why:** `_unit()` infers units from suffixes. Neither key matches its suffix table, so both fall back to dimensionless. Existing result cards and `primary_quantity()` correctly identify these metrics as m/s.

**Suggested fix:** Add explicit metadata for these keys, preferably using a shared metric-to-unit registry.

### 6. Low — Unknown output names silently succeed

**What goes wrong:** Request `outputs=["max_vm_mpa"]` from a model containing `max_vm_pa`. MCP returns `is_error=False`, `results=[]` and a normal interpolation summary. A mixed request silently omits unknown names.

**Why:** `predict()` filters available outputs without validating the requested names. An in-memory MCP reproduction confirmed the successful empty response.

**Suggested fix:** Reject unknown names with `err.surrogate_outputs`, listing the model’s available outputs.
