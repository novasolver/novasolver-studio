# v0.5 second-opinion fixes

Scope: `reviews/v0.5_fix_brief.md` and all seven findings in
`reviews/2026-10-29_since-9ffe633.codex.md`, on branch `v0.5`.

| Finding | Change | Regression coverage |
|---|---|---|
| 1. References and extra loads | `reference_loads.unsupported_loads` is shared by cantilever, plate-hole, thermal-block, fin, electric, modal and the new structural template references. It rejects gravity, rotation and thermal loads outside each formula's coverage, and face roles outside the template's analytic pattern. The reason identifies the load/face/role; its message is localized in ja/en/zh. Cantilever also requires its modeled transverse load direction. | `test_reference_identifies_unmodeled_body_load` (all 13 applicable templates), `test_reference_identifies_unmodeled_face_role` (including an unknown future role). |
| 2. Quadratic sections and clicks | Sub-tetrahedra define cap geometry only. Each intersection's scalar and displacement are evaluated with the original element's quadratic shape functions and inverse map, reusing the point-probe interpolator. Clipped surface intersections use it too. Section clicks send the undeformed picked coordinate to the original-element point probe, pinned to the selected run. | `test_section_uses_original_quadratic_interpolant` (`uz` and modal fields): `u_z=x²` at `x=.25` gives `.0625` within `1e-9`. `frontend/tests/faces-undo.cjs` checks that the numerical click value comes from the point response, with the correct coordinates/run/mode, and that stale point responses are discarded. |
| 3. Role changes | Boundary normalization revalidates retained quantities, point vectors, components and directions. Invalid retained fields use the new role's defaults; incompatible fields are dropped. Explicit direction edits share the same validation. The direction picker offers `normal` only for `load`. | `test_role_change_revalidates_retained_direction` (moment, bearing, remote-force; moment load assembly also runs), `frontend/tests/boundary-directions.cjs` (renders the real selection editor). |
| 4. Disconnected modal parts | Mesh connectivity defines components. Each gets its own rigid-body basis and constraint-rank calculation. The solver requests the requested elastic count plus the total remaining nullity, then skips exactly that count. CalculiX frequency compilation and postprocessing use the same component count. Sparse basis storage avoids a dense global component matrix in the direct path. | `test_disconnected_modal_skips_twelve_rigid_modes`: two free blocks have 12 rigid modes, return six converged elastic modes and match the single-block first elastic frequency within 1%. It also checks fixed and partial supports per component. Existing `test_11_mass_and_lobpcg_branch` passes. |
| 5. CalculiX temperature results | Compute the applied temperature once, pass that same array into compilation, and save it with the structural results plus `t_min_k`/`t_max_k`. | `test_calculix_preserves_applied_temperature_contract` (uniform and solved temperature). A fake executable/result parser allows both tests everywhere. They compare the deck and saved field, check extrema, `field("temp")`, a point probe and CSV export. The thermal solve itself is real. |
| 6. Remote-force points | Every `point` must convert to exactly three finite coordinates. Scalars, malformed shapes and nonfinite values produce structured path errors before case mutation. | `test_remote_point_requires_three_finite_coordinates`, including `"25 mm"`, bare/dictionary scalars, incorrect lengths, null, nested and nonfinite input. `test_remote_point_accepts_finite_vectors` checks both supported vector forms and unit conversion. |
| 7. Stale line probes | A request generation token is invalidated on case/run/mode changes and unmount. Responses also check the current store selection. Stale errors and completion handlers cannot affect a newer request. Probe HTTP requests carry the selected run ID. | `frontend/tests/results-tools.cjs` exercises the real LinePlot with deferred replies for mode/run/case changes, unmount, a current reply, and an old rejection while a new request is busy. `test_probe_http_pins_requested_run` checks HTTP forwarding. |
