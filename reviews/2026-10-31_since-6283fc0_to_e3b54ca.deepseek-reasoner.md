## 1. The new Link component types children as React.ReactNode but never imports the React namespace, so the file fails TypeScript compilation.
- where: frontend/src/components/HelpDialog.tsx:13
- scenario: `npm run build` or `tsc` in the frontend -> TS2686/Cannot find namespace 'React' in HelpDialog.tsx, blocking the build.
- fix: Import `type ReactNode` from "react" and use `children: ReactNode`.

## 2. Paths are interpolated into single-quoted PowerShell literals without doubling apostrophes, so an install/data path like C:\Users\O'Brien breaks the swap script (and allows PowerShell injection via the path).
- where: backend/update.py:139
- scenario: App installed under C:\Users\O'Brien\NovaSolverStudio -> SWAP script contains $app = 'C:\Users\O'Brien\...' -> syntax error, update never applied; crafted folder name executes arbitrary PowerShell.
- fix: Escape single quotes ('' ) or pass paths via -File/-EncodedCommand arguments or environment variables instead of string interpolation.

## 3. Global shortcuts still fire while the new HelpDialog is open because the guard checks s.palette but not s.help.
- where: frontend/src/App.tsx:32
- scenario: Open Help and press Ctrl+Z -> undoCase() runs and mutates the case behind the modal; h/x also hide faces or toggle see-through.
- fix: Add `!s.help` to the shortcut guard and handle Ctrl+K only when no modal is open.

## 4. Check-then-act race: state is only set to 'applying' after Popen, so two concurrent update requests both pass the 'ready' guard and spawn two swap scripts on the same folders.
- where: backend/novastudio/updates.py:196
- scenario: User triggers update twice (double click / client retry) -> both requests read state=='ready' -> two PowerShell scripts rename/move NovaSolverStudio concurrently -> half-moved install / data loss.
- fix: Guard and flip _job to 'applying' under a threading.Lock before launching Popen; abort if not idle.

## 5. _download catches only OSError/ValueError/BadZipFile; any other exception (http.client.HTTPException like IncompleteRead, RuntimeError from an encrypted/unsupported zip, KeyError on metadata) kills the thread leaving _job['state']='downloading' forever.
- where: backend/update.py:84
- scenario: Server truncates the response body -> IncompleteRead is raised inside _get -> thread dies, state stays 'downloading' -> start_download() returns status() unchanged and never retries until app restart.
- fix: Wrap the whole _download body in try/except BaseException and always set state='error' with the exception name.

## 6. startUpdate's 500ms poll interval is only cleared on a successful status reply; if api.updateStatus keeps throwing (e.g. backend restarts/dies mid-download) it polls forever.
- where: frontend/src/state/store.ts:1206
- scenario: Start an update, then the backend is restarted by applyUpdate or crashes -> updateStatus rejects -> catch 'keep polling' -> a request every 500ms for the rest of the session (log spam / resource leak).
- fix: Track failure count or an abort flag and clearInterval after N consecutive errors; also clear updatePoll in startUpdate's catch before returning.

## 7. The non-portable fallback also catches kind "other" and shows the pip/Python update instructions, which are wrong for other install kinds.
