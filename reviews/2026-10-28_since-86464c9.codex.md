### 1. Medium — Failed selection updates are never retried

**What goes wrong:** Select face A successfully, then select B while `/api/gui-state` encounters a transient failure. The GUI shows B, but `get_gui_selection` continues returning A. Asking the AI to “fix these faces” can therefore apply the boundary condition to A.

**Why:** `guiSignature` advances before the request succeeds. After failure, subsequent state updates with the same shared fields return at line 175 without scheduling another request. Reconnection and hovering do not retry it. An in-memory probe confirmed this behavior.

**Suggested fix:** Track unsent state separately from acknowledged state and retry failed requests with bounded backoff. Always retry the latest snapshot.

### 2. Medium — “Same direction” selects curved faces

**What goes wrong:** An imported part contains a planar face and a narrow cylindrical face whose average normal lies within 2° of that plane. Selecting the plane and clicking “Same direction” also selects the cylinder. Applying a temperature, flux, or other condition then changes both surfaces.

**Why:** The descriptor code assigns `normal` whenever the average triangle-normal magnitude exceeds `.999`, regardless of CAD surface type. A Gmsh probe confirmed that a **4° cylindrical face** receives this normal. `selectSameDirection` then accepts every descriptor with a normal, without requiring a planar type.

**Suggested fix:** For CAD, emit planar normals only for `Plane` surfaces. Also restrict the frontend action to planar descriptors. For STL groups, verify planarity across the group before classifying it as a plane.

### 3. Medium — Rectangle selection blocks on occluded meshes

**What goes wrong:** Ctrl-drag across a densely tessellated solid with a hidden rear face. Every rear triangle inside the rectangle triggers another full-mesh raycast. A two-layer, **6,400-triangle** in-memory probe took approximately **1.6 seconds** synchronously; larger meshes become substantially less responsive.

**Why:** Occluded faces never enter `found`, so all their triangle centroids are tested. Each test traverses the merged mesh, producing quadratic worst-case work on the UI thread.

**Suggested fix:** Use an ID/depth buffer or spatially accelerated intersection queries. Keep expensive selection work off the main thread or process it in cancellable chunks.
