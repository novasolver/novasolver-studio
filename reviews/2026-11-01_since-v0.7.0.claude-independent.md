# Independent pre-release review: v0.7.0 → c5cfc31 (NovaSolver Studio 0.7.1)

Reviewer: Claude (independent, read-only). Scope: `git diff v0.7.0 c5cfc31 -- backend frontend/src integrations`
plus the code each change calls into. Every finding below comes from reading the code. Findings marked
**(uncertain)** are inferences I could not confirm by reading alone. I did not run the tests or the app.

Note: the working tree is not clean relative to c5cfc31. `contact.py` caps `k2` at 256, and `mesh_worker.py`
excludes plane-vs-plane seams from `smooth`. Both changes are uncommitted. Line numbers refer to the working tree
where it matches c5cfc31.

| R3 | medium (security) | backend/novastudio/config.py:77-89 (`_scratch_run`), archive.py:41-43 | `_scratch_run` checks only path *names*: `wd.name=='of'`, `run.parent.name=='runs'`, and that the grandparent resolves to a root. | R4 | medium | backend/novastudio/contact.py:180-188 (as of c5cfc31, no cap) | The retry query uses `k2 = reach.max()`, where the radius is `size.max() + 2*search` taken over the whole master. Slave points that legitimately have no master (most of a slave face larger than the contact zone, for example the Hertz cyl_surface) are always in `miss`. One large master element therefore pushes `k2` toward `len(Xm)` for every missed point. `tree.query(P_miss, k=k2)` allocates P_miss×k2×16 B (≈72k points × a few thousand ≈ several GB per 500-element chunk), and the Newton loop runs k2 Python iterations over all missed points. The result can be an out-of-memory error or a very slow contact setup. The uncommitted cap of 256 bounds this, but c5cfc31 has no cap. | Commit the cap. Better, retry only the points whose own `query_ball_point` count exceeds k, grouped by their own count (or query per point with its own k), and use each point's local radius instead of `size.max()`. |

## Checked and found OK

- `--import` argparse: `--units` and `--lang` have choices, the path is passed as a list (no shell), and Blender and
  FreeCAD always pass absolute temp paths, so a path starting with `-` is not reachable. Non-ASCII and space-containing
  paths go through `CreateProcessW` and `Path.resolve()`. `import_geometry` copies the bytes immediately
  (`read_bytes`), so a later overwrite of the temp STL cannot race the import. An old 0.7.0 exe exits with 2 on
  `--import` (unrecognised arguments).
- `plane_and_blend_labels`: the median is only taken over ≥2 ids. With no flat edges, `components` still labels every
  triangle. Empty seam arrays go through `bincount` safely. Labels never cross a feature-angle group, because every
  adjacency is filtered by `group[a]==group[b]`, so `labels.max()+1 <= len(groups)` correctly means "no split".
  Element tags survive `createTopology`, the same mechanism as the existing labelled remesh path. The volume path with
  `ref_faces` labels from `faces_display`, which now carries the split faces, so it stays consistent.
- Fatigue: the second `support_peak` call uses the same `nodes`/`fixed`, so `max_vm_away_pa` exists whenever the
  first one did. `results.py` falls back for results from older versions that lack `fatigue_life_min_away`. In
  `primary_quantity`, the away value equals the global minimum when the minimum is away from supports, so mixing it
  across levels stays consistent.
- `templates.face_descriptors` for Hertz: the axis (z through (0, hb+R)) and radius in metres match `mesh_worker`
  (addCylinder(0,hb+R,0,…)) and the other Cylinder descriptors, which are converted ×1e3 only in commands.py.
- i18n: backend 632/632/632 and frontend 568/568/568 keys, with identical placeholders in ja, en and zh, including
  `{gci:.2g}`. `t()` uses `str.format`, so the format spec works.
- Frontend `verification.reference == null`: VerificationLine guards it, ResultsStep's fallback grid uses `fmt()`
  (null renders as "—"), and ShareMenu and ViewerPane use only `error_pct`. exports.py guards the convergence branch.
- `linear_solve` fall-through: `MemoryError` leads to AMG-CG (non-contact) or GMRES (contact). `MatrixRankWarning` from
  the new direct path is caught by the Newton loop (fem_nonlinear.py:427).
- Contact retry recursion terminates: the inner call's `reach.max()` over a subset is ≤ k2.
