## 1. High — CFD boundary edits do not reach the solvers

**What goes wrong:** Set cavity `boundaries.x0.role="moving-wall"` and its speed to `2 m/s`. The UI accepts the change, but the solver still treats that wall as stationary. In-memory comparison confirmed that the generated OpenFOAM files are identical before and after this edit.

**Why:** `external.py:363–370` combines three cavity faces into hard-coded stationary walls. The channel compiler similarly hard-codes its boundary pattern. The built-in cavity path at `run_worker.py:295` passes only Reynolds number and grid size to a solver with fixed boundary conditions. The final cavity reference check tests Reynolds number without checking the edited boundary pattern.

**Suggested fix:** Compile every supported face condition, or restrict these templates to the boundary conditions their solvers implement. Reject unsupported edits before solving and validate the complete reference pattern.

## 2. High — Material validation depends on the selected template

**What goes wrong:** A plate-hole case accepts `materials.solid.E="-1 GPa"` and `materials.solid.nu=0.75`. A single-element reproduction with negative Young’s modulus reversed the displacement while retaining finite values and force imbalance of approximately `6.6e-17`, satisfying the built-in convergence criteria.

**Why:** Generic material edits receive bounds only when their paths appear in that template’s parameter list. Editable paths expose additional properties without universal physical validation.

**Suggested fix:** Validate scalar shape, finiteness, and physical ranges independently of templates: positive modulus/conductivity/viscosity and an admissible Poisson ratio. Apply this validation again before solving.

## 3. High — Thermal mesh verification can measure prescribed boundary data

**What goes wrong:** Run a CalculiX convergence study on an imported conductor with faces fixed at 20°C and 100°C. The study can track the imposed 80 K difference on every mesh and report zero grid error while heat flow remains mesh-dependent.

**Why:** CalculiX thermal postprocessing computes face flows but omits `metrics.q_in_w` at `external.py:265–272`. `primary_quantity()` therefore falls back to `t_max_k - t_min_k`, even with two prescribed temperatures.

**Suggested fix:** Return consistent heat-flow metrics from both thermal engines. Select a solution-dependent quantity for verification and refuse to verify a study whose monitored quantity is imposed by its boundary conditions.

## 4. High — Nonconverging grid sequences can become “verified”

**What goes wrong:** For meshes with `h=[1, 0.5, 0.25]`, values `[100,101,102]` produce `asymptotic=false` but GCI ≈2.94%, allowing the study to pass. Values `[1,0.5,0]` produce GCI=0 despite a substantial final change.

**Why:** The pass condition ignores `asymptotic`. Additionally, `gci()` substitutes zero relative error whenever the final value is zero.

**Suggested fix:** Treat divergent or indeterminate sequences as insufficient evidence for verification. Handle near-zero quantities with a meaningful absolute scale/tolerance; never replace an undefined relative error with zero.

## 5. High — Noncircular passages can receive the wrong flow model

**What goes wrong:** A 100 mm × 1 mm rectangular inlet is assigned diameter 11.28 mm; its hydraulic diameter is approximately 1.98 mm. At 1 m/s with water viscosity `1e-6 m²/s`, this changes the Reynolds number from approximately 1,980 to 11,284 and triggers the application’s turbulence switch.

**Why:** `_hyd_diameter()` calculates circular-equivalent diameter from area alone. It is used for Reynolds number, mesh sizing, and turbulence length scales.

**Suggested fix:** Calculate hydraulic diameter as `4A/P` using the wetted perimeter. Preserve circular-equivalent diameter separately where that quantity is intended.

## 6. High — Debounced edits can modify the next case

**What goes wrong:** Change case A’s force, then switch to case B before the 300 ms save timer fires. The queued force is PATCHed into B. A Node reproduction recorded a PATCH to B containing A’s edit.

**Why:** `pending` stores paths and values without their owning case ID. `flush()` obtains the destination from the currently open payload. Switching cases does not settle or isolate pending edits.

**Suggested fix:** Associate each edit queue with its original case ID and revision. Settle saves before switching, or maintain independent queues that always save to their original case.

## 7. High — Delayed fields can cross case boundaries

**What goes wrong:** Start loading A’s stress field, open B, then let A’s request complete. B’s current state receives A’s field. This was reproduced in Node.

**Why:** `loadField()` captures the original payload but never checks case identity or request freshness before committing its response. Its error path can also clear a newer field.

**Suggested fix:** Check case ID, requested quantity, and request generation before updating state. Abort superseded requests and apply equivalent guards to error paths.

## 8. High — Revision checks are not atomic

**What goes wrong:** GUI and MCP clients submit different edits with `expected_revision=1` concurrently. Both can succeed, returning revisions 2 and 3, while the second save restores an old value and loses the first edit. This was reproduced with an in-memory store.

**Why:** Loading, checking the revision, applying changes, and saving occur without a shared lock. `store.save()` rereads the current revision but writes a case constructed from an earlier snapshot.

**Suggested fix:** Protect the entire read/check/change/save transaction with a per-case interprocess lock shared by HTTP and MCP. The second conflicting writer must receive HTTP 409/the corresponding tool error.

## 9. High — `run_id` escapes its case directory

**What goes wrong:** Request A’s results with `run_id="../../c_casebbbb/run/r_other"`. The loader selects B’s result. If revisions match, the response can report `stale=false` and all verification gates true under A’s case context. This was reproduced with mocked file reads.

**Why:** `latest_done_run()` directly joins an unchecked `run_id` onto the run directory and does not validate result ownership.

**Suggested fix:** Validate run IDs against their exact generated format, resolve the path, and require it to be an immediate child of the requested case’s run directory. Validate stored case ownership as well.

## 10. High — The local API trusts arbitrary web origins

**What goes wrong:** An unrelated website can connect to `/ws`, obtain active job IDs, and submit a simple POST to `/api/jobs/{id}/stop`. ASGI tests accepted `Origin: https://untrusted.example` for both operations.

**Why:** The WebSocket is accepted without origin validation, and mutation routes lack origin/token protection. Binding to loopback does not establish which website initiated a request.

**Suggested fix:** Validate Host and Origin, including WebSocket handshakes. Require an unpredictable application token for mutations and socket access, with explicit handling for authorized development origins.

## 11. Medium — Conjugate results fail when heating uses temperature or convection

**What goes wrong:** A conjugate case heated through a fixed-temperature face has no `heat-flux` input, so `q_in=0` and `heat_balance=NaN`. Returning its results raises `ValueError: Out of range float values are not JSON compliant`. The serialization failure was reproduced.

**Why:** Heat input includes only prescribed fluxes. The code stores NaN for other valid configurations and also allows `converged=true` whenever `q_in==0`, without checking the recorded residual.

**Suggested fix:** Account for heat transfer through temperature and convection boundaries. Use JSON `null` for unavailable metrics and require valid residual/balance evidence before declaring convergence.

## 12. Medium — Millimetre-scale template boxes cannot identify faces

**What goes wrong:** Valid 1 mm and 10 mm cubes produce no recognized face keys and fail meshing. Direct Gmsh checks returned six `None` keys for both sizes.

**Why:** The tolerance is `1e-5 * maximum_dimension`, smaller than the padding in OCC bounding boxes for these geometries.

**Suggested fix:** Use an absolute tolerance floor consistent with OCC precision, or identify faces through their underlying planes and centers rather than padded bounding-box thickness.

## 13. Medium — Conjugate body roles cannot be changed

**What goes wrong:** The documented update `{"bodies.b1.role":"fluid"}` returns `err.role`, listing face roles instead of accepting the body role. This was reproduced.

**Why:** The generic `key=="role"` branch runs before the body-specific branch, making the latter unreachable.

**Suggested fix:** Handle body roles before boundary roles, or dispatch validation by the full path.

## 14. Medium — Offered convergence studies fail for supported case kinds

**What goes wrong:** Request convergence for a channel or conjugate case. The first solve runs, then the job fails with `no study quantity for channel_of` or `... conjugate`.

**Why:** `primary_quantity()` handles neither result kind, while both HTTP/MCP and the UI expose the operation without a capability check.

**Suggested fix:** Define suitable monitored quantities for these kinds. Until implemented, reject the request immediately with an actionable unsupported-operation error and disable the UI action.

## 15. Medium — MCP crashes on a missing extrapolated value

**What goes wrong:** A study finishes within the MCP wait period with `extrapolated=null`. Instead of reporting its result, `check_convergence` raises `TypeError: unsupported format string passed to NoneType.__format__`. This was reproduced.

**Why:** `.get("extrapolated", 0)` returns `None` when the key exists with a null value; the formatter then applies `:.5g`.

**Suggested fix:** Explicitly format unavailable extrapolation as unavailable, preserving the study’s gates and diagnostics.

## 16. Medium — Curved-element probes use straight-element coordinates

**What goes wrong:** For a curved tet10, a physical point `[0.25,0.225,0.25]` was interpolated with weights corresponding to `[0.25,0.1975,0.25]`. Even a field linear in physical coordinates is therefore read incorrectly.

**Why:** The locator derives barycentric coordinates from the four corners, then applies quadratic interpolation weights. CAD meshes explicitly permit curved midside nodes.

**Suggested fix:** Invert the quadratic isoparametric geometry mapping when locating/interpolating tet10 points. Use curved-element containment checks as well.

## 17. Medium — Quadratic face averages ignore midside nodes

**What goes wrong:** A straight tri6 face with corner temperatures 0°C and midside temperatures 100°C reports mean temperature 0°C; its quadratic area mean is 100°C. This was reproduced through `probe()`.

**Why:** Face averages use only `tri[:, :3]`, despite accepting quadratic surface elements.

**Suggested fix:** Integrate the field with the surface element’s shape functions and Jacobian. Use appropriate quadrature for curved faces and derived quantities.

## 18. Medium — External solvers have no enforced wall-time limit

**What goes wrong:** A stalled CalculiX/OpenFOAM process can run beyond the case’s default `max_wall_s=900` indefinitely, blocking every queued solver job.

**Why:** `_proc_once()` waits until process exit or a STOP flag. It never checks the case timeout, while the worker retains the machine-wide solver slot.

**Suggested fix:** Enforce a deadline throughout external execution, terminate and reap the process tree on timeout, and persist a specific timeout failure before releasing the slot.

## 19. Medium — Constraint components cannot be edited in the UI

**What goes wrong:** Select the `constraint` role and try to change its default `"xy"` components to `"z"`. The editor displays an empty numeric field; numeric submissions are rejected by the backend.

**Why:** Only `direction` receives a string editor. `components` falls through to `NumberInput`, although its contract requires a nonempty subset of `"xyz"`.

**Suggested fix:** Render component checkboxes or a dedicated selector and submit the component string.

## 20. Medium — Packaged MCP setup points to a nonexistent Python executable

**What goes wrong:** In a packaged installation, opening the AI panel generates a command beneath `Documents/NovaSolverStudio/.venv/Scripts/python.exe`, which the packaged application does not install.

**Why:** The frontend infers the application location from the workspace path and assumes a development virtual environment. Frozen installations deliberately keep workspace and application resources in different locations.

**Suggested fix:** Return the actual MCP launch command and arguments from the backend. For frozen builds, use the packaged executable with its `mcp` subcommand.

## 21. Low — Language switches retain old field labels

**What goes wrong:** Load a result in Japanese, then switch to English. Other labels refresh, but the color bar and exported legend retain the Japanese field label.

**Why:** Language changes call `loadResults(false)`. For the same run with an existing field, that path skips reloading the language-dependent field payload.

**Suggested fix:** Refresh field metadata when language changes, or translate field labels locally from stable quantity IDs.

No missing locale keys or cross-language placeholder mismatches were found in the English, Japanese, and Chinese dictionaries.
