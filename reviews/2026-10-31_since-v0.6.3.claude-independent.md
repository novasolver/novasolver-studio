# Independent review: v0.6.3..HEAD (2026-10-31)

Scope: `git diff v0.6.3..HEAD -- backend frontend/src tools build_release.ps1 installer .github integrations`.
Focus areas were the print check, the desktop window and single-instance code, packaging and integrations, and MCP.
contact.py, fatigue.py, buckling and fem changes were only skimmed.

Measured (isolated LOCALAPPDATA and workspace in a temp folder, builtin FEM preview): cantilever template, PLA,
200x20x20 mm, 1000 N tip load, x0 `fixed`. Hand calculation gives σ_root = 150 MPa. print_check gives an x-axis layer
tension of 154.6 MPa at (2.44, 2.44, 20) mm, sf 0.16. The max sxx including the support nodes is 170 MPa. y/z layer
tension is 48/28.5 MPa at (1.62, 7.37, 18.57) mm, 1.6 mm from the clamp. vm_max_mpa is 142 MPa, so it is below the
nodal sxx of 154.6 MPa.

## High

### H1. running.json is never removed on a normal exit. Blender and FreeCAD then post to a dead or foreign port
- `backend/novastudio/__main__.py:110,123-136`, `desktop.py:45-55`, `integrations/blender/novasolver_studio/__init__.py:154-179`, `integrations/freecad/NovaSolverStudio.FCMacro:55-65`
- Input: run Studio once, close the window, then click "Analyze in NovaSolver Studio" in Blender (or run the FreeCAD macro).
- Output: `running_port()` returns the old port. The integration skips starting Studio and POSTs to `127.0.0.1:<old port>`, which raises URLError/ConnectionRefused. This is the normal state after the first use, so the integration fails whenever Studio is not already running. If another local program now listens on that port, it receives the user's STL/STEP model.
- Fix: unlink running.json in a `finally` at the end of `_app`, only when its pid is ours. The integrations should also check that the recorded pid is alive (or call `GET /api/env` and check a Studio-specific field) before trusting the port, and start Studio otherwise.

## Medium

### M1. Print check: transverse stresses next to a fixed face count as layer tension and can pick the "best" direction
- `backend/novastudio/printcheck.py:48-51,59,69`
- Only the nodes on the fixed face are excluded. The Poisson-constraint singularity spreads one to two elements into the part. In the measurement above, the y/z "layer tension" (48 / 28.5 MPa) sits 1.6 mm from the clamp and is an artefact. `run_worker.support_peak` already uses a 2×median-edge reach (`run_worker.py:~180`), but printcheck does not reuse it. `support_peak_exceeds` only compares vm and only flags above 1.2× the remaining peak, so the user gets no warning.
- Fix: use the same reach-based "away" mask as `support_peak`. Report the per-axis peak at the support separately and add a warning when the governing value lies within that reach.

### M2. Print check: `beam-clamp` nodes are excluded, but a beam clamp has no singularity, so the real maximum is dropped (unconservative)
- `printcheck.py:21` (`FIXED_ROLES = ("fixed", "beam-clamp")`)
- Input: a cantilever with `x0: beam-clamp` (the template variant at templates.py:573) and a tip load. The true peak bending stress is at the clamp face. Excluding it reports the stress about h/2 inboard (the next row of tet10 nodes), so the SF is too high by about h/(2L), with no warning.
- Fix: exclude only `fixed` (and possibly `constraint`) faces. Never exclude `beam-clamp`.

### M3. Print check ignores interlaminar shear; the "best" direction can be one that delaminates in shear
- `printcheck.py:68-73`
- Only σ_nn along the build axis is compared with the layer bond. Example: a beam in bending printed with layers parallel to its axis (build direction = load direction) has σ_zz ≈ 0, so sf_layers = ∞. The check then reports the filament SF and prefers this direction, but the peak τ_xz at the neutral axis loads the layer bond directly. For short, stubby parts such as hooks this can govern.
- Fix: use the traction on the layer plane, σ_n = s_nn and τ = √(s_n1² + s_n2²) from the shear components (indices 3..5 = xy, yz, zx). Apply an interaction criterion such as (⟨σ_n⟩/Z)² + (τ/S)² ≤ 1 with a default S, or at least report τ and warn.

### M4. Print check does not enforce "linear-elastic only" and ignores multi-material assemblies
- `printcheck.py:36-41`
- `physics.kind` is always `linear-static` for structural cases (templates.py:175/295/345), and `results.kind` is `structural` for nonlinear, elastoplastic and large-deformation runs too (run_worker.py:322). API and MCP therefore accept these runs. In large deformation the stresses belong to the deformed configuration while `at_mm` and the layer axes are undeformed. The UI hides the section when `r.curve` is set; the API and MCP do not.
- Assemblies: if `body_materials` gives some bodies steel or aluminium while `materials.solid.preset == "pla"`, the check runs over every node and applies PLA strengths to the metal parts.
- Fix: refuse when `physics.analysis == 'nonlinear'` or the results contain `curve`/`step_*`. Restrict the check to nodes of PLA/PETG/ABS bodies (via `tet_body`), or refuse when `body_materials` is non-empty.

### M5. A second start that times out falls through and starts a second server without the lock
- `__main__.py:103-110`
- Input: double-click a `.nscase` (or start twice) while the first instance takes more than 10 s from acquiring the lock to `inst.publish`. That is plausible on a cold frozen start with antivirus scanning, because `.api` (gmsh, scipy, matplotlib) is imported before publish.
- Output: after 100 × 0.1 s the second process unlinks running.json and starts its own server on the next free port without holding the lock (`inst.fh` is None). The first instance then overwrites running.json. The user ends up with two servers and two windows, and the integrations may target either one. Needs run to confirm the timing.
- Fix: after the loop, keep waiting (for example up to 60 s, while the lock is still held) or exit with a message. Never fall through when `acquire()` failed.

### M6. Window mode quits silently when the browser exits immediately
- `__main__.py:124-128`, `desktop.py:108-123`
- Input: Edge or Chrome is present but exits at once. Examples: an enterprise policy blocks `--user-data-dir` or app mode, a broken install, or the profile directory is not writable.
- Output: `proc` is not None, so `hide_console()` runs. `wait_closed` sees no lockfile and a finished process and returns at once. The server stops and the program ends. The user sees nothing, not even the console. Needs run.
- Fix: if `proc.poll()` is not None within a few seconds and no lockfile ever appeared, fall back to `webbrowser.open(url)` and the console loop. Hide the console only after the lockfile has appeared.

### M7. Blender add-on offers TPU, which is not a Studio preset
- `integrations/blender/novasolver_studio/__init__.py:30,109-112`, `store.py:430-433`
- Input: Material = TPU. The import succeeds, then the PATCH `materials.solid.preset=tpu` returns 400 `err.path`. The add-on reports an HTTPError and never opens the case, and an orphan case with the default material is left in the workspace. TPU is also hyperelastic, so a linear preset would be misleading anyway.
- Fix: remove TPU (or add a preset with a non-linear warning). Validate against `/api/templates` or the materials list, and open the case even when the material PATCH fails.

### M8. An all-users Inno install is classed "portable" and the self-updater writes into Program Files
- `installer/NovaSolverStudio.iss:29-30` (`PrivilegesRequiredOverridesAllowed=dialog`), `updates.py:103-113,224`
- Input: in the setup dialog the user picks "install for all users". The app goes to `C:\Program Files\NovaSolverStudio`, `install_kind()` returns `portable`, and the update UI offers an in-place update that cannot replace the folder without elevation. Needs run.
- Fix: drop the override (per-user only), or detect a non-writable `STUDIO_ROOT` (or `Program Files` in the path) and return a kind such as `installer` that only links to the setup download. Even for a per-user install, an in-place update leaves Inno's DisplayVersion and uninstall log stale. Consider having the updater run the new setup.exe in silent mode for Inno installs.

## Low

- **L1** `printcheck.py:53-56`, `api.py:289`, MCP `print_check`: a strength of `0` is silently replaced by the default (`if strength_xy_mpa:`). `inf` is accepted and yields SF = ∞ everywhere; `nan` gives the generic error. Fix: `is not None` plus a `math.isfinite(v) and v > 0` check.
- **L2** `frontend/src/components/ResultsTools.tsx:~87-90`: typing a negative strength (for example `-5`) makes the request fail, `setData(null)` runs, and the whole section including the input fields disappears. The section stays hidden for that case until the case changes or the page reloads, so the user cannot correct the value. Fix: keep the last good data and show the error under the input. Debounce the requests.
- **L3** `printcheck.py:65,74`: `vm` (averaged scalar) and `s` (averaged tensor) are smoothed differently. Measured: vm_max 142 MPa < nodal sxx 154.6 MPa. The filament check therefore uses a slightly lower stress than the uniaxial stress at the same spot. Fix: compute vm from the averaged `s`, or use max(vm, |principal|).
- **L4** `printcheck.py:74`: when several axes are limited by the same filament SF (ties), `max()` returns x and the UI labels it "best/おすすめ". Fix: report ties, or rank ties by sf_layers.
- **L5** `printcheck.py`: no stale flag. A run solved under another material or load still gets checked against the current preset. Fix: pass `stale` through as get_results does.
- **L6** `mcp_server.py:~456-471`: the docstring says peaks on fixed faces "are reported separately", but the text summary omits `support_peak_*` and the screening caveat (they are only in structured_content). Fix: add one line to the summary.
- **L7** `pyproject.toml:48` (`samples/*.step`) and `backend/novastudio/samples/`: `wall_hook.stl` is in neither, so pip/uvx installs silently lack the new sample (`list_samples` filters out missing files). Fix: add `samples/*.stl` and copy the file into the package samples folder.
- **L8** `config.py:28-34` docstring ("a cloud AI never sees the shape"): numbers-only mode withholds images only. `import_geometry`/`get_case` still return bbox, face centroids and areas (mcp_server.py:213-221), and probe returns coordinates. Fix: change the wording to "no images", or add a mode that also withholds coordinates.
- **L9** `backend/tests/test_printcheck.py:16`: `while "results" not in r` never ends once `job_status` takes over, because `job_status` has no `results` key. A preview that takes longer than 60 s (70 s here) makes the test spin for up to an hour. Fix: loop on `r["state"] != "done"` and then call `get_results`.
- **L10** Integrations: when Studio is not running, the add-on and macro start `program` with no arguments (which opens a Start window) and later `program --case`, which opens a second window. FreeCAD's `send_step` blocks the GUI thread for up to 180 + 600 s. Fix: start with `--case` only after import, or pass the file directly. Run the FreeCAD request in a thread or QTimer loop.
- **L11** `.github/workflows/release-windows.yml`: `signpath/github-action-submit-signing-request@v1` receives `SIGNPATH_API_TOKEN` but is pinned to a mutable tag. Pin third-party actions to a commit SHA. Dependencies come from `pip install -e .` without a lock or hashes, so releases are not reproducible. The smoke step says "MCP tool list" but only checks `env`.
- **L12** `tools/fetch_build_deps.py:41,59`: the post-extract hash checks use `assert` and are skipped under `python -O`. Use an explicit `if ...: sys.exit(...)`. The download hashes themselves are pinned and correct in form.
- **L13** `tools/make_msix.py`: `desktop6:FileSystemWriteVirtualization` needs Windows 10 1903 (18362), but `MinVersion=10.0.17763.0`. `Version="{version}.0"` breaks for pre-release versions such as `0.7.0-rc1`. `unvirtualizedResources` is a restricted capability that needs Store justification. Needs run with makeappx.
- **L14** `examples.py:64-82`: the index and the files may come from different hosts (the order puts the last-used host first, per call). A stale mirror then gives a hash mismatch with no fallback to the other host. Also, an index fetched from the mirror makes the mirror its own trust root, so the "sha256 checks either copy" comment overstates the guarantee. Fix: fetch index and files from the same host, and on a mismatch retry the other host.
- **L15** `backend/novastudio/__init__.py:6` and `frontend/package.json`: still `0.6.3`. The workflow fails on a `v0.7.0` tag until the version is bumped (intended guard, noted as a reminder).

## Checked and found OK
- Stress component order: indices 0..2 are sxx, syy, szz in fem_tet10, fem_nonlinear and CalculiX (`S[:,:6]`), matching probe.py's `(xx, yy, zz, xy, yz, zx)`. Units: Pa internally, MPa in and out. inf is converted to null by `api._finite`, and the UI shows null as ∞.
- `--case` is validated by a strict regex. `.nscase` is accepted only as an existing file and is passed to `import_case` only. The browser is started with a list of arguments (no shell) and a URL built from an int port plus the validated id, so no injection was found.
- The server binds to 127.0.0.1. The Host and Origin checks are unchanged. The Inno association command is `"{app}\NovaSolverStudio.exe" "%1"`, correctly quoted, under HKA.
- The lockfile is released by the OS when the process dies, and a crash leaves no permanent "already running" state (but see H1 for running.json).
- i18n: every `print.*`, `buckling.*`, `update.store` and `update.offlineMode` frontend key exists in ja, en and zh, and the backend has `err.print_check_*` in all three.
- The update apply path refuses any kind other than `portable`, so Store installs are safe.
