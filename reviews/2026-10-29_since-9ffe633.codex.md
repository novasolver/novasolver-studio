## 1. High — Verification can pass against a reference that excludes active loads

**What goes wrong:** Start with the default cantilever and enable gravity with `g="100000 m/s2"` and direction `"+x"`. In an in-memory solve, this added **62,800 N** axially, yet the transverse tip-displacement reference still passed: computed **0.97014 mm**, reference **0.98307 mm**, error **−1.315%** against a 3% tolerance. With `ran=true`, the verification gate passes despite comparing different loading problems.

**Why:** `reference_cantilever` and `reference_plate_hole` inspect face conditions but ignore the newly supported gravity, rotation, and thermal loads. The guards in `structural.reference` do not cover these two templates.

**Suggested fix:** Check all active load sources before declaring either reference applicable. Disable the analytical comparison for unsupported combinations, or extend its formula to include those loads.

## 2. High — Section probes can report substantially wrong values

**What goes wrong:** For a straight tet10 with nodal displacement representing `u_z=x²`, a section at `x=0.25 m` should show **62.5 mm**. Calling `section_field` returned **125 mm** throughout the cap—a reproduced 100% error.

**Why:** The code subdivides each tet10 into linear tetrahedra and passes nodal values to `slice_plane`, which interpolates linearly. This changes the quadratic solution. The viewer then reports these approximate cap scalars as probe values.

**Suggested fix:** Evaluate cap values using the original tet10 shape functions at each intersection point. For numerical click readouts, query the original element interpolator at the picked coordinate.

## 3. Medium — Switching a normal load to a moment crashes the job

**What goes wrong:** Set `boundaries.x1.direction="normal"` on a load face, then change only its role to `"moment"`. The resulting boundary retains `"direction":"normal"`. Solving raises `ValueError: substring not found` in `structural.direction`. This was reproduced in memory.

**Why:** Boundary normalization preserves fields shared by both roles without checking whether their values remain valid. Explicit direction updates reject `"normal"` for moments, but role changes bypass that validation.

**Suggested fix:** Revalidate retained values when changing roles. Replace incompatible directions with the new role’s default, and filter the GUI direction options accordingly.

## 4. Medium — Disconnected assemblies do not produce the requested elastic modes

**What goes wrong:** Run free-free modal analysis on two disconnected solid blocks, requesting six elastic modes. The reproduction returned five near-rigid frequencies around **0.0011–0.00345 Hz**, with `converged=false`, instead of useful elastic modes.

**Why:** `modal_constraints` constructs six rigid-body modes for the entire mesh. Two disconnected solids have twelve. The solver requests too few eigenpairs and treats another rigid eigenvalue as the first elastic value when filtering.

**Suggested fix:** Detect connected mesh components and construct/count rigid modes per component, including each component’s constraints. Alternatively, reject disconnected modal models with an actionable explanation before solving.

## 5. Medium — Final thermal-stress results lose temperature

**What goes wrong:** Configure `thermal-bar-free` with solved temperatures of 0 °C and 100 °C at opposite ends, then run CalculiX final analysis. The temperature is applied during compilation, but the saved structural results contain only `u`, `vm`, and `s`. Temperature disappears from the available quantities, probes, and exports; requesting `field(...,"temp")` falls back to another quantity.

**Why:** `compile_calculix` computes `T` locally, while `run_calculix` neither retains it nor saves temperature extrema. The built-in structural path saves both.

**Suggested fix:** Carry the applied temperature field into postprocessing and save `T`, `t_min_k`, and `t_max_k`, matching the built-in result contract.

## 6. Medium — Scalar remote-force coordinates silently alter the load

**What goes wrong:** Submit a remote-force point as `"25 mm"` through `update_case`. It is accepted as a scalar. The force calculation broadcasts it as **[25, 25, 25] mm**, generating a moment about that unintended location instead of rejecting the malformed point.

**Why:** Validation checks vector length only when the converted value is already a list. A finite scalar passes, and NumPy broadcasts it in `point-center`.

**Suggested fix:** Require every `point` value to contain exactly three finite coordinates, regardless of its input representation. Return a structured validation error before updating the case.

## 7. Medium — A late probe response can display the previous mode’s curve

**What goes wrong:** Start a line probe for mode 1, then select mode 2 before the request finishes. The mode-change effect clears the chart, but the outstanding mode-1 response subsequently calls `setData`, restoring the old curve while mode 2 remains selected.

**Why:** Clearing state does not invalidate outstanding requests. The response handler checks neither the selected mode nor the run that initiated it.

**Suggested fix:** Use a request generation token or cancellation, and discard responses whose case, run, or mode no longer matches the current selection.
