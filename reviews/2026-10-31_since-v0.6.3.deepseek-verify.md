# Verification of DeepSeek since-v0.6.3 findings (subset)

Source: `reviews/2026-10-31_since-v0.6.3.deepseek-reasoner.md`. Checked by reading the code, read-only.
Scope: items 1, 2, 3, 4, 5, 8, 10, 11, 13, 14, 15, 16, 17, 19, 20, 21, 22, 23, 24, 26, 27, 28, 29, 30, 31, 32, 34, 36, 37, 38.
i18n claims were checked with a script that loads `templates.TEMPLATES` and all three backend catalogs (all template
title/description/verify/param/face-label keys present in ja/en/zh; the catalogs have the same key set).

Result: 4 REAL, 4 PARTLY, 22 FALSE.

## Real / partly real

| # | verdict | sev | where | evidence | minimal fix |

| 8 | REAL (from before v0.6.3) | medium | backend/novastudio/config.py:64-65 | On win32 `roots = [data_dir()]` only. `data_dir()` is `%LOCALAPPDATA%\NovaSolverStudio` (osdirs.py:11-19), under the user profile. With a non-ASCII user name (common on Japanese Windows) the job folder is unsafe, the only fallback is just as unsafe, and `roots[-1]` is used anyway, so MinGW OpenFOAM runs from a non-ASCII path. test_platform.py:249 tests darwin only. The run fails with an error. It does not give a wrong answer. | Add an ASCII Windows candidate before data_dir, e.g. `Path(os.environ.get('PUBLIC') or os.environ.get('ProgramData') or 'C:\\ProgramData') / 'NovaSolverStudio'`. If no candidate is safe, raise a clear StudioError instead of using an unsafe root. Add a win32 case to test_platform. |
| 30 | REAL (from before v0.6.3) | low | backend/novastudio/config.py:63-67 | The scratch folder `root/runs/<job>_<tag>/of` is never deleted: `of_location.txt` is only written (config.py:67) and skipped by archive (archive.py:32). Nothing reads it when a case or run is deleted. Only OpenFOAM jobs whose path is non-ASCII or has spaces are affected, and these folders can be hundreds of MB. | On case/run delete, read `of_location.txt` and `shutil.rmtree` the target when it lies under the scratch root. |
| 13 | REAL | low | backend/novastudio/results.py:128-130 | When `fatigue_on_support` is set, the SF card shows `fatigue_sf_min_away` but the life card shows the global `fatigue_life_min`, which is taken at the support singularity. The two cards describe different points. | 5 | REAL | low | backend/novastudio/structural.py:417-419 | gap-blocks uses `d = abs(uz)`. | 1 | PARTLY | low | backend/novastudio/templates.py:714 | Every gap_blocks/hertz face gets a bare `type:'Plane'` with no normal/bbox/area, so `cyl_surface` has no Cylinder descriptor. | 32 | PARTLY | low | backend/novastudio/contact.py:154-180 | `_project` only tests the k=8 nearest master centroids. With strongly graded master meshes (a large element next to many small ones) the containing element can be missed, and that quadrature point is dropped as "no hit". This only weakens the averaged row (A_i). It is reported as no contact only if every point misses (err.contact_pair_none). It is not silent with uniform meshes. | For points still at -1 after the loop, retry with a radius query `tree.query_ball_point(p, size.max()+search)` (or k*=4). |
| 37 | PARTLY | low | backend/novastudio/run_worker.py:714 | The mesh study tracks `fatigue_sf_min` for fatigue-bar. The template's supports are rollers/constraint-x (templates.py:518-519), so the stress is uniform and the study converges. Only if the user sets x0 to `fixed` does the minimum sit on the singularity and fail to converge. | Use `fatigue_sf_min_away` when `fatigue_on_support` is true (same rule as results.py:128). |
| 26 | PARTLY (mostly false) | low | backend/novastudio/templates.py:510, 623 | Force 0 is accepted. For buckling it is handled explicitly: `max_strain == 0` gives no factors (fem_tet10.py:689-691), so the user gets `err.buckling_none` with a "no load" message. Hertz reference handles P=0 (structural.py:364-368). Nothing divides by zero. This is only a UX nit. | Optional: lower bound 1e-6 (or >0) on load fields of these templates. |

## Incidental (outside the list)

- `err.no_temperature` (structural.py:140, from 0.5) has no key in any backend catalog (only `check.no_temperature`
  exists). `t()` falls back to the raw key, so a thermal-stress case with `thermal_load.mode = 'solve'` and no
  temperature face shows "err.no_temperature". Fix: raise `check.no_temperature`, or add `err.no_temperature` to ja/en/zh.
